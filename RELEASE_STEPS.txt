JIMMY NEXT RELEASE STEPS
========================

This repository (C:\claude\JimmyNext, GitHub Jimr9/JimmyNext) builds Jimmy Next only.
Production Jimmy lives in its own checkout and repository (Jimr9/Jimmy); never build,
tag or publish production Jimmy from here. Setup_WiX\Jimmy.wxs is the historical
production installer source and is NOT used for Jimmy Next releases.

Do not bump the version, tag or publish unless Jim asks. CLAUDE.md's "Release
Versioning" section is the authoritative checklist; this file gives the commands.

Private inputs (git-ignored, never committed or printed):
   - WSJTX_Controller\SupportService.key   (support service access key; without it the
     support features say "not available")
   - Club Log key file (Jimmy.csproj ClubLogKeyFile, or JIMMY_CLUBLOG_KEY_FILE)
Prepared inputs (git-ignored, regenerated by script):
   - EngineHost\.nexus-src                 scripts\prepare-nexus.ps1
   - WSJTX_Controller\Resources\hamlib     fetch-hamlib.ps1
   - EngineHost runtime DLLs               EngineHost\stage-runtime-dlls.ps1 (MSYS2 UCRT64)

1. Bump the version (only when asked):
   - WSJTX_Controller\Properties\AssemblyInfo.cs: AssemblyFileVersion, AssemblyInformationalVersion
     (AssemblyVersion stays frozen at 1.0.0.0)
   - Setup_WiX\JimmyNext.wxs: Package Version and the header comment
   Keep JimmyNext.wxs's UpgradeCode {594D5C69-67A3-40E2-A5D9-68289DCAB98A} unchanged.

2. Prepare and build EngineHost (release). From the repo root:
   powershell -ExecutionPolicy Bypass -File scripts\prepare-nexus.ps1
   powershell -ExecutionPolicy Bypass -File fetch-hamlib.ps1
   then from EngineHost\ with C:\msys64\ucrt64\bin first on PATH:
   cargo build --release
   then: powershell -ExecutionPolicy Bypass -File stage-runtime-dlls.ps1

3. Publish Jimmy Next (from Setup_WiX\):
   dotnet publish ..\WSJTX_Controller\Jimmy.csproj -c Release -p:AssemblyName="Jimmy Next" -p:SelfContained=true -r win-x64 -o PublishOutputNext
   (delete PublishOutputNext\ and WSJTX_Controller\obj\Release first, so this is a full
   rebuild and no stale file is packaged)

4. Build the installer (from Setup_WiX\):
   wix extension add -g WixToolset.UI.wixext/5.0.2     (once per machine, if "wix extension list -g" lacks it)
   wix build -ext WixToolset.UI.wixext -arch x64 -o Release\JimmyNext.msi JimmyNext.wxs
   The WIX8600 warning about an empty Resources\* file group is expected (that folder
   holds only subfolders).

5. Verify (from Setup_WiX\):
   powershell -ExecutionPolicy Bypass -File verify_jimmynext_msi.ps1
   Checks ProductVersion, the "Jimmy Next.exe" File table version and MajorUpgrade.
   Also confirm "Jimmy Next.dll" contains the SupportService.key resource name and the
   packaged jimmy-engine-host.exe matches EngineHost\target\x86_64-pc-windows-gnu\release.
   Optional install test: Setup_WiX\InstallTest\JimmyNextInstallTest.wsb (Windows Sandbox).

6. Zip and hash:
   Compress-Archive Release\JimmyNext.msi Release\JimmyNext.msi.zip -Force
   Get-FileHash Release\JimmyNext.msi, Release\JimmyNext.msi.zip -Algorithm SHA256

7. Publish (only when Jim says so):
   git push origin <branch>            (origin = Jimr9/JimmyNext)
   git tag vX.Y.Z ; git push origin vX.Y.Z
   gh release create vX.Y.Z --repo Jimr9/JimmyNext Release\JimmyNext.msi Release\JimmyNext.msi.zip
   Never use Jimr9/Jimmy. Website (blindsea.com/jimmy20) updates are a separate step.
